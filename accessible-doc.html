Command-line workflows

The command line is a universal interface for modelling/simulation, which is at the core of our group's research.

  • The command line is often simpler to explain to new students and postdocs than graphical user interfaces.
  • The command line is also an effective way to convey core concepts that apply to graphical user interfaces such as VS Code and R Studio.
  • The command line is relevant to all of our computation settings, from local devices to cloud virtual machines and high-performance computing platforms.

Interactive training materials are useful, but when presented in videos the text can be blurry, even illegible, and cannot be copied.

Asciinema

Asciinema is a lightweight text-based tool for recording and sharing terminal sessions. It allows us to play back terminal sessions, and to select and copy text!

See the asciinema website for further details.

An example asciinema recording

On this slide I present an asciinema recording that show hows to change the editor used to write git commit messages, and switches been nano and vim. I will pause the recording and show that we can select and copy text.

Some limitations of asciinema

Recording a terminal session in real-time doesn't necessarily yield the best teaching materials.

So I createdasciinema-scripted, a tool that lets you write a script for asciinema. This means that you can, for example:

  • Plan ahead rather than perform live!
  • Control the input speed and insert pauses
  • Define chapter markers relative to input events
  • Display comments in a "subtitle" bar

An example asciinema-scripted recording

On this slide I present a demonstration recording generated by asciinema-scripted, where I show how to list file sizes and calculate the total size of all files in the directory. There is a subtitle bar at the bottom of the terminal that explains what I want to achieve with each command that is run.

The demo script (YAML)

On this slide I show most of the YAML script that was used to generate the recording from the previous slide.


actions:
- action_id: Comment
  comment: See what files are here
- ls
- action_id: Comment
  comment: How large are these files?
- action_id: Input
  text: du -h *
  pre_nl_delay: 1
  post_nl_delay: 3
- action_id: Marker
  label: Sum disk usage of all files
- action_id: Comment
  comment: What is the total disk usage?
- action_id: Input
  text: du -c -h * | grep total
  pre_nl_delay: 1
  post_nl_delay: 3
- action_id: Comment
  comment: Goodbye
- '# The end'
- action_id: Marker
  label: END
- exit
